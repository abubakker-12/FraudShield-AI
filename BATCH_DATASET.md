# Batch prediction input contract

Use **Batch Prediction → Download synthetic examples** for a 25-row CSV from the bundled demo. The **Download CSV template** button supplies the same nine required headers. The benchmark files are generated temporarily and are outside the release manifest.

## Format and limits

- UTF-8 comma-separated CSV with one header, optionally starting with a UTF-8 BOM. Use ordinary CSV double-quote escaping for values containing commas or newlines. Excel workbooks, JSON, TSV, compressed archives and other encodings are unsupported in this UI.
- Public limits are **5,000,000 bytes (5 MB)** and **25,000 data records**, enforced independently. Source record numbers are one-based positions after blank rows are skipped.
- Headers are exact and case-sensitive, with no duplicates. Column order is flexible. Optional columns such as transaction IDs, notes or target labels are ignored. Omitting `is_fraud` and `fraud_type` is preferable. These columns do not enter preprocessing, inference, or export.
- Required values cannot be missing. Blanks, pandas' default missing markers such as `NA`, `N/A` and `NULL`, nonfinite numbers, and values outside the accepted ranges are rejected. Invalid UTF-8, embedded null bytes, malformed CSV, headers without records and inconsistent row widths are also rejected.
- A single field is subject to Python's CSV parser field-size limit, including ignored columns. Keep optional fields short for predictable upload and parse costs.

| Required header | Expected value | Example |
|---|---|---|
| `hour_of_day` | Integer 0–23, 24-hour clock | `23` |
| `is_international` | Integer 0 or 1 | `1` |
| `failed_attempts` | Integer 0–1,000 | `2` |
| `pin_changed_recently` | Integer 0 or 1 | `0` |
| `time_since_last_txn_hrs` | Finite number, 0–1,000,000 hours | `2.5` |
| `transaction_amount` | Finite number, 0.01–1,000,000,000,000. Use a plain number without a currency symbol or thousands separator | `150.25` |
| `merchant_category` | Category text, 1–80 characters after trimming | `Grocery` |
| `payment_method` | Category text, same rule | `Credit Card` |
| `device_type` | Category text, same rule | `Mobile` |

### Model vocabulary

- **Merchant category**: ATM Withdrawal, Clothing, Crypto Exchange, Education, Electronics, Entertainment, Fuel, Gaming, Grocery, Healthcare, Jewelry, Online Shopping, Restaurant, Travel, Utilities.
- **Payment method**: Bank Transfer, Cheque, Credit Card, Crypto, Debit Card, Mobile Payment.
- **Device type**: ATM, Desktop, Mobile, POS Terminal, Tablet.

Unknown nonempty category text within the length limit is accepted. The fitted encoder ignores unknown levels. Category matching is case-sensitive after trimming. The record has no inferred date, currency or customer information.

## Results and privacy

The export covers all scored rows and includes source record number, model score, stored threshold and model version, flag, and prediction label. It omits uploaded optional data and categorical source values. All exported fields are numeric or generated by the application. The existing case-export formula escaping still applies to reviewer-entered content.

Upload and prediction data are scoped to the browser session. Full uploads are never sent to Groq. SHAP and Copilot are invoked for individual investigations only. Public uploaded-row investigations use Python. SQLite stores a case only when an individual analysis is explicitly opened.
